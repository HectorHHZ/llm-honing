# Hollow Knight (ForestDango) Exp 0 v0 dataset card

This dataset supports the paired `read` and `probe` experiment of [#185](https://github.com/HectorHHZ/llm-honing/issues/185) under [#174](https://github.com/HectorHHZ/llm-honing/issues/174), with the accepted Griddly Spiders v0 release as the reference. It uses the full Hollow Knight remake of ForestDango with the Honing bridge on a deterministic development build, and the frozen no-autopilot harness `v12_standing`: the model reads structured English text about what is on the screen, never pixels, and answers two questions per decision (movement keys and attack key). One episode runs from a scripted start in King's Pass to the group's waypoint (win), the knight's first death (loss) or the cap of {{DECISION_CAP}} model decisions (timeout). The {{SCORED_EPISODES}} scored episodes come from {{RESET_GROUPS}} reset groups; a group's clean and changed episodes share one split and are one statistical unit.

Outcomes come from native game signals read by the evaluation side only (the game's debug trace, never shown to the model): win = standing inside the waypoint box, loss = the death counter rises or health reaches 0, timeout = the {{DECISION_CAP}}-decision cap ({{FRAME_CAP}} native frames as a second cap), other terminal = leaving King's Pass. {{ATTEMPTS}} formal attempts were made and {{EXCLUDED}} were excluded (reasons in `evaluator/attempts.jsonl`); {{RESERVE_NOTE}} The scored episodes contain {{MODEL_DECISIONS}} model decisions ({{MODEL_QUESTIONS}} question records, two questions per decision), {{AUTO_ROWS}} `auto` rows (native windows the harness played without a model decision while the knight was off screen), {{NATIVE_WINDOWS}} native windows and {{MODEL_INPUT_TOKENS}} model-server input tokens (Laya's own token audit); their `decisions.jsonl` files total {{DECISION_BYTES}} bytes. Decisions, windows and questions are counted separately from episodes; adjacent windows are not independent episodes.

**Groups.** The {{RESET_GROUPS}} reset groups are ten starts on one reference route through one area (King's Pass): a new game and nine places along the route, each reached by a scripted key prefix from a new game; the waypoints follow the same route. They are correlated: they share the area, the route, the enemies and the policy, and later starts contain the way of earlier ones in the harness's memory. Splits (`train`/`val`) are recorded per group for the shared format; they do not separate areas. The clean outcome of each group was known before the freeze from its development pilot (an exact replica on the deterministic build); the rule chose every start whose clean policy reached its waypoint, so the clean controls are {{CONTROL_WIN}} wins and {{CONTROL_TIMEOUT}} timeouts by design (no clean pilot died).

**Labels.** Labels record the component changed in the actual episode. Harness evidence is the logged request next to the clean render of the same saved state: {{HARNESS_EVIDENCE_SUMMARY}} Weights evidence is the first request identical (byte for byte, same native tick) to the matched clean episode's whose probabilities differ by more than {{TOLERANCE}}: {{WEIGHTS_EVIDENCE_SUMMARY}} Across the {{PER_CONDITION}} weights cases the maximum option probability difference ranges from {{WEIGHTS_DP_MIN}} to {{WEIGHTS_DP_MAX}}, and the chosen option at the evidence row differed from the clean partner's in {{WEIGHTS_CHOICE_CHANGED}} (`choice_changed` in the index). Controller evidence is the selected keys next to the sent keys: {{CONTROLLER_EVIDENCE_SUMMARY}} Reference-action annotations are unavailable. Whole-episode effects are recorded separately (`outcome_effect` is `not_established`; the paired clean outcome is in each index row); release-level score drop is untested. {{OUTCOME_PAIRING_SUMMARY}} {{FOLLOW_SUMMARY}}

**Checks.** {{CHECKS_SUMMARY}} Label isolation of the diagnosis inputs: {{ISOLATION_SUMMARY}}.

The versioned `honing-exp0-episode-v0` records (contract {{CONTRACT_VERSION}}, schemas in `schemas/`) live in `evaluator/`: `evaluator/episodes.json` maps the neutral ids to attempts and gold labels, `split-manifest.json` records group membership, `evaluator/attempts.jsonl` records every attempt with its status, and `evaluator/weights-reask.jsonl` holds the clean service's replies to the weights episodes' evidence requests. Per attempt: `manifest.json` (pins, start, waypoint, handover state), `decisions.jsonl` (requests exactly as sent, raw-reply references, both questions' probabilities, the chosen options, executed windows with the keys asked for and sent, native events, the visible observation after each decision), `responses/*.raw` (raw reply bytes), `public_states.jsonl` (the exact harness state saved before each decision, for re-rendering) and `result.json`. The attempts' `extra/` directories (the game's own logs, per-frame state logs, process receipts) are not released. No released file holds an absolute local path or the local account name: the decision services' local checkpoint `path` fields are removed by `bundle.py`, any other occurrence in a record would be replaced by a placeholder (`<workspace>`, `<home>`, `<conda-root>`, `<user>`, `<local-path>`; counts in `privacy-check.json`), and the code resolves local locations at run time (`runtime.py`). `sha256.json` covers the file set. Use the [label guide](LABELS.md) for the evidence and the [runbook](RUNBOOK.md) to reproduce and verify. The dataset is for development and reproducibility: one verified intervention instance per component, one route in one area, correlated episodes within and across reset groups. {{KNOWN_LIMITS}}
