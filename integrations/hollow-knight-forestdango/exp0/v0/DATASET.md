# Hollow Knight (ForestDango) Exp 0 v0 dataset card

This dataset supports the paired `read` and `probe` experiment of [#185](https://github.com/HectorHHZ/llm-honing/issues/185) under [#174](https://github.com/HectorHHZ/llm-honing/issues/174), with the accepted Griddly Spiders v0 release as the reference. It uses the full Hollow Knight remake of ForestDango with the Honing bridge on a deterministic development build, and the frozen no-autopilot harness `v12_standing`: the model reads structured English text about what is on the screen, never pixels, and answers two questions per decision (movement keys and attack key). One episode runs from a scripted start in King's Pass to the group's waypoint (win), the knight's first death (loss) or the cap of 40 model decisions (timeout). The 40 scored episodes come from 10 reset groups; a group's clean and changed episodes share one split and are one statistical unit.

Outcomes come from native game signals read by the evaluation side only (the game's debug trace, never shown to the model): win = standing inside the waypoint box, loss = the death counter rises or health reaches 0, timeout = the 40-decision cap (1600 native frames as a second cap), other terminal = leaving King's Pass. 40 formal attempts were made and 0 were excluded (reasons in `evaluator/attempts.jsonl`); no reserve group was collected. The scored episodes contain 1,291 model decisions (2,582 question records, two questions per decision), 0 `auto` rows (native windows the harness played without a model decision while the knight was off screen), 2,743 native windows and 1,984,507 model-server input tokens (Laya's own token audit); their `decisions.jsonl` files total 8,094,575 bytes. Decisions, windows and questions are counted separately from episodes; adjacent windows are not independent episodes.

**Groups.** The 10 reset groups are ten starts on one reference route through one area (King's Pass): a new game and nine places along the route, each reached by a scripted key prefix from a new game; the waypoints follow the same route. They are correlated: they share the area, the route, the enemies and the policy, and later starts contain the way of earlier ones in the harness's memory. Splits (`train`/`val`) are recorded per group for the shared format; they do not separate areas. The clean outcome of each group was known before the freeze from its development pilot (an exact replica on the deterministic build); the rule chose every start whose clean policy reached its waypoint, so the clean controls are 4 wins and 6 timeouts by design (no clean pilot died).

**Labels.** Labels record the component changed in the actual episode. Harness evidence is the logged request next to the clean render of the same saved state: in the 10 harness episodes the first changed request is at model decision 0 (10 episodes); 325 of their 325 model requests differ from the clean render. Sentences of the state text left out of the actual requests, by kind: “Ground” 265, “Ledges near you” 150; no sentence was added; the questions, the option order and the option texts differ in 0 requests. Weights evidence is the first request identical (byte for byte, same native tick) to the matched clean episode's whose probabilities differ by more than 0.01: 10 by `matched_clean_identical_request`; evidence at model decision 0 in 10 of 10 weights episodes; the largest option probability difference at the evidence row is 0.4314–0.7629 (over both questions), and the most probable option of at least one question changed in 10 of 10. The re-ask record holds 10 clean-service replies to the evidence requests of 10 weights attempts. Across the 10 weights cases the maximum option probability difference ranges from 0.4314 to 0.7629, and the chosen option at the evidence row differed from the clean partner's in 10 (`choice_changed` in the index). Controller evidence is the selected keys next to the sent keys: the first swapped decision is model decision 0 (10 episodes); 290 of the 290 directional selections (293 model decisions) were executed with the other direction; every changed window keeps the selected keys as `intended_action`. Reference-action annotations are unavailable. Whole-episode effects are recorded separately (`outcome_effect` is `not_established`; the paired clean outcome is in each index row); release-level score drop is untested. Same native status as the paired clean episode of the group: harness 8/10, weights 6/10, controller 5/10. Selections compared with the paired clean episode's, decision by decision (same start): harness: 1 of 10 identical to the end, the others first differ at model decision 0–3 (median 1); weights: 0 of 10 identical to the end, the others first differ at model decision 0; controller: 0 of 10 identical to the end, the others first differ at model decision 1–3 (median 1).

**Checks.** Validator over all attempts: `{"valid":40}`. Probe self-check: 1,291 logged requests of 40 attempts re-rendered byte for byte from their saved states, 0 mismatches. Native replay on the deterministic build (a new game process fed only the attempt's recorded native input, from the boot on): 40 of 40 attempts identical in every debug state per window (7,935/7,935), every visible observation (7,935/7,935) and every per-frame state record (55,247/55,247; the object count `nGo` left out, it differed in 76 frames). 10 of 10 clean controls sent exactly the requests of their group's development pilot (same bytes, decision by decision, up to the control's end). Label isolation of the diagnosis inputs: passed: 0 forbidden markers (fault family and instance names with '-', '_' and ' ' equal, run and group-condition names, checkpoint repos, revisions and SHA-256s, any 64-hex digest, label field names); uniform markers: `alternate-checkpoint` (probes/probe-inputs.jsonl, all 40 episodes).

The versioned `honing-exp0-episode-v0` records (contract 0.2.0, schemas in `schemas/`) live in `evaluator/`: `evaluator/episodes.json` maps the neutral ids to attempts and gold labels, `split-manifest.json` records group membership, `evaluator/attempts.jsonl` records every attempt with its status, and `evaluator/weights-reask.jsonl` holds the clean service's replies to the weights episodes' evidence requests. Per attempt: `manifest.json` (pins, start, waypoint, handover state), `decisions.jsonl` (requests exactly as sent, raw-reply references, both questions' probabilities, the chosen options, executed windows with the keys asked for and sent, native events, the visible observation after each decision), `responses/*.raw` (raw reply bytes), `public_states.jsonl` (the exact harness state saved before each decision, for re-rendering) and `result.json`. The attempts' `extra/` directories (the game's own logs, per-frame state logs, process receipts) are not released. No released file holds an absolute local path or the local account name: the decision services' local checkpoint `path` fields are removed by `bundle.py`, any other occurrence in a record would be replaced by a placeholder (`<workspace>`, `<home>`, `<conda-root>`, `<user>`, `<local-path>`; counts in `privacy-check.json`), and the code resolves local locations at run time (`runtime.py`). `sha256.json` covers the file set. Use the [label guide](LABELS.md) for the evidence and the [runbook](RUNBOOK.md) to reproduce and verify. The dataset is for development and reproducibility: one verified intervention instance per component, one route in one area, correlated episodes within and across reset groups.
