# VVVVVV Exp 0 v0 dataset card

This dataset supports the paired `read` and `probe` experiment of [#185](https://github.com/HectorHHZ/llm-honing/issues/185) under [#174](https://github.com/HectorHHZ/llm-honing/issues/174), with the accepted Griddly Spiders v0 release as the reference. It uses the original VVVVVV (source `40e1ec3b` with the merged `integrations/vvvvvv` bridge of upstream main `9d5327f1`) and the integration's default observation: the full bridge observation as structured text, never pixels. One episode runs from the native Space Station 1 time-trial start to the room after "Conundrum" (win), with deaths respawning at the game's checkpoint, or to the cap of 150 model decisions (timeout). The 40 scored episodes come from 10 reset groups; a group's clean and changed episodes share one split and are one statistical unit.

| Condition | Complete | Win | Loss | Timeout | Other terminal | Deaths (sum) | Model decisions |

| No injection | 10 | 2 | 0 | 8 | 0 | 36 | 1,355 |

| Weights | 10 | 0 | 0 | 10 | 0 | 0 | 1,500 |
| Controller | 10 | 0 | 0 | 10 | 0 | 11 | 1,500 |

Outcomes come from native game signals: win = the player enters a room other than `[113,105]` and `[114,105]`; a death (the native death sequence or counter) is recorded as an event and the episode goes on; timeout = the 150-decision cap. No episode can end in a loss under this rule; the column is kept for the shared format. 40 formal attempts were made and 0 were excluded (reasons in `evaluator/attempts.jsonl`); no reserve group was collected. The scored episodes contain 5,671 model decisions (5,671 question records, one question per decision), 146 `auto` rows of the death animation, 5,817 native windows and 2,196,663 model-server input tokens (Laya's own token audit); their `decisions.jsonl` files total 20,144,296 bytes. Decisions, windows and questions are counted separately from episodes; adjacent windows are not independent episodes.

**Groups.** The 10 reset groups are 10 policy seeds from one native start in one layout (two rooms). They are correlated: every episode starts in the same state and faces the same rooms, and a group's four conditions share the seed (common random numbers), so a changed episode follows its clean partner until the change acts. #185: "Extra seeds do not establish new layouts". Splits (`train`/`val`) are recorded per group for the shared format; with one layout they do not separate layouts.

**Labels.** Labels record the component changed in the actual episode. Harness evidence is the logged request next to the clean render of the same saved state: in the 10 harness episodes the first changed request is at model decision 0 (10 episodes); 1,316 of their 1,316 model requests differ from the clean render, and only in `localSolidRows`. Weights evidence is the first request identical (byte for byte, same native tick) to the matched clean episode's whose probabilities differ by more than 0.01: 10 by `matched_clean_identical_request`; at the evidence row p(`flip`) was 0.3403–0.3403 under the clean checkpoint and 0.9911–0.9911 under the alternate. All 10 evidence rows are the same request: every reset group starts from the same native state, so the first request (and its two probability vectors) is identical in every group; the weights evidence therefore rests on one request. The re-ask record holds 10 clean-service replies to the first requests of 10 weights attempts, each differing by 0.6508–0.6508 from the logged alternate reply. Across the 10 weights cases the maximum option probability difference ranges from 0.6508 to 0.6508; the most probable option changed in 0 of them, and the sampled choice at the evidence row differed from the clean partner's in 7 (`choice_changed` in the index compares the sampled choices). Controller evidence is the selected input next to the sent input and the bridge's echo: the first swapped decision is model decision 0 (7 episodes), 1 (1 episodes), 2 (1 episodes), 3 (1 episodes); 889 of 1,500 model decisions were sent mirrored (every directional selection); the bridge echoed the sent input at every decision: yes. Reference-action annotations are unavailable. Whole-episode effects are recorded separately (`outcome_effect` is `not_established`; the paired clean outcome is in each index row); release-level score drop is untested. Same native status as the paired clean episode of the group: harness 9/10, weights 8/10, controller 8/10. Selections compared with the paired clean episode's, decision by decision (same seed, same start): harness: 2 of 10 identical to the end, the others first differ at model decision 0–123 (median 22); weights: 0 of 10 identical to the end, the others first differ at model decision 0–3 (median 0); controller: 0 of 10 identical to the end, the others first differ at model decision 1–15 (median 4).

**Checks.** Validator over all attempts: `{"valid":40}`. Probe self-check: 5,671 logged requests of 40 attempts re-rendered byte for byte, 0 mismatches. Native replay (fresh game process, logged inputs only): 40 of 40 attempts reproduced every logged observation and the outcome (5,817 native windows). The integration's own receiver accepted 5,671 of 5,671 executed replies of all attempts.

The versioned `honing-exp0-episode-v0` records (contract 0.2.0, schemas in `schemas/`) live in `evaluator/`: `evaluator/episodes.json` maps the neutral ids to attempts and gold labels, `split-manifest.json` records group membership, `evaluator/attempts.jsonl` records every attempt with its status, and `evaluator/weights-reask.jsonl` holds the clean service's replies to the weights episodes' first requests. Per attempt: `manifest.json`, `decisions.jsonl` (requests exactly as sent, raw-reply references, probabilities, the sampled choice, executed windows, native events, the bridge observation after each window), `responses/*.raw` (raw reply bytes), `public_states.jsonl` (the saved observation for re-rendering) and `result.json`. The attempts' `extra/` directories (process receipts, game logs, local paths) are not released. No released file holds an absolute local path or the local account name: the decision services' local checkpoint `path` fields are removed by `bundle.py`, any other occurrence in a record would be replaced by a placeholder (`<workspace>`, `<home>`, `<conda-root>`, `<user>`, `<local-path>`; counts in `privacy-check.json`), and the code resolves local locations at run time. `sha256.json` covers the file set. Use the [label guide](LABELS.md) for the evidence and the [runbook](RUNBOOK.md) to reproduce and verify. The dataset is for development and reproducibility: one verified intervention instance per component, one layout, correlated episodes within and across reset groups.
