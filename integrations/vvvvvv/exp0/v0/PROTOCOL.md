# VVVVVV Exp 0 v0 protocol

Evaluate one component diagnosis per complete native episode. The primary endpoint is component accuracy on 30 verified interventions, with abstentions and invalid outputs scored as incorrect. Compare `read` and `probe` on the same 40 episodes. The ten no-injection controls measure unsupported component accusations: a control false positive is an asserted component fault without supporting audit evidence (#185). [Issue #185](https://github.com/HectorHHZ/llm-honing/issues/185) · [Exp 0 #174](https://github.com/HectorHHZ/llm-honing/issues/174) · reference: the accepted Griddly Spiders v0 release.

## Collection

Use the original VVVVVV source `TerryCavanagh/VVVVVV@40e1ec3b` built with the bridge of `integrations/vvvvvv` at upstream main `9d5327f1` (binary SHA-256 `47cca96b72687ed8876a1229ada58420d06677bd81fabc18d429e5388a7eb9f0`; the caller's official desktop `data.zip`, SHA-256 `c767809594f6472da9f56136e76657e38640d584164a46112250ac6293ecc0ea`, stays local). No speed-up bridge, no developer hooks and no lookahead are used in any dataset run. The decision request is the merged integration's own `run.request_for`: its rule text plus the full bridge observation as JSON (player position and velocity, gravity, deaths, room, checkpoint, the 9x9 local tile rows around the player with `#` solid, `!` spike, `.` clear, and the current room's entities; never pixels), and the six raw inputs `wait`, `left`, `right`, `flip`, `flip_left`, `flip_right`, each held for 15 native ticks (0.51 s). There is no autopilot and no hidden or ranked option. The controller is the integration's `NativeClient` and bridge; decision shape `native` (one decision, one native window). The collector checks the decision server's weights SHA-256 before and after each episode, and every reply must pass both the common guard (`contract.guard_response`) and the integration's own receiver (`checked_action`, exact six-option set) before any native input.

The clean checkpoint is Laya `convaiinnovations/laya-typed-decisions@1a793eb5` (weights `4fa56de7…`, service 8813). The alternate is `jayzou3773/laya-ra2-v33@51d2f5a0` (weights `2ed46ac9…`, service 8814), a Red Alert 2 fine-tune of the same Laya, served by the same server code. Both run on CPU in FP32.

One episode ("一局") starts at the native Space Station 1 time-trial start (room `[113,105]` "Welcome Aboard", player at x 200, y 161, gravity down, after the native 165-tick countdown) in a fresh game process. It is a **win** when the player enters a room other than `[113,105]` and `[114,105]` "Conundrum" (the spike-pit room that must be crossed on the ceiling). A death is not terminal: the game's death animation runs as `auto` rows of `wait` windows (no model call) and the player respawns at the game's own checkpoint. It is a **timeout** at 150 model decisions. Selection: seeded sampling from the model's probabilities (`contract.Sampler`, one draw per decision over the request's options in request order), with one fixed policy seed per reset group shared by the group's four conditions; with the highest-probability choice the clean policy plays `flip` at every decision and never leaves the start (phase 1, 30/30).

There is one start and one layout. The reset groups `s01`–`s10` (policy seeds 1–10, reserves `s11`–`s16`, seeds 11–16) are policy seeds from that one start, so the groups are correlated; #185: "Extra seeds do not establish new layouts". Take the first ten listed groups for each condition. Collect reserve groups, in listed order, only for a slot with no eligible attempt after its attempt cap (3 per slot), or for controls when all ten share one outcome; keep all attempts. Select non-wins first for intervention conditions, in plan order within an outcome bucket; include both winning and non-winning controls when the eligible attempts contain them (Griddly v0 PROTOCOL line 9, as `audit_set.py` implements it). Keep native loss, other terminal status and the cap distinct. The plan was frozen before the first release attempt (`collection.json`, SHA-256 `93a1013eeea6f3133003353c3b97af794f1a464f3d5f74c42cb83c8fb5a5a0a7`).

The three interventions are persistent for the whole episode:

- Harness (`omit-local-terrain-persistent-v1`, #185 "Omit available floor/ground information"): at every model decision the request is rendered from the state with the 9x9 local rows showing solid and spike cells as clear; options, option texts and every other field are unchanged. The collector keeps the logged request and the clean render of the same state (`clean_request`), and the pre-harness public observation keeps the true rows. The brief's default instance, removing the `flip` option, makes every request invalid for the integration's receiver (exact option set; measured on a phase-1 request), so this #185 instance was used instead; it is the same family as the full-HK release's `omit-ground-v1`.
- Weights (`laya-ra2-v33-v1`): the alternate checkpoint serves the whole episode. Evidence: the first request identical (byte for byte, same native tick) to one of the matched clean episode of the same reset group whose normalized probabilities differ by more than 0.01 in any option; the same request re-asked on the clean service is kept as well (`weights-reask.jsonl`).
- Controller (`swap-left-right-persistent-v1`): after the selection, at every decision whose selected input has a direction, left and right are exchanged (`left`↔`right`, `flip_left`↔`flip_right`); `wait` and `flip` are sent unchanged. Every changed window keeps the selected input (`intended_action`) and the sent one; the bridge's echo of the sent input is in the next observation.

Validate every attempt against the episode contract (0.2.0) and record all incomplete, untriggered, rejected and unselected attempts. Every attempt was replayed natively: a fresh game process fed only the logged executed inputs reproduced every logged observation and the outcome. Use the matched clean result as separate outcome evidence. This v0 collection records per-decision component effects; release-level score drop is untested. Pilots (phase 1 on 2026-11-23, groups `p01`–`p04`, and the persistent-fault pilot on group `p01` on 2026-11-26) were used for development and are outside the scored set; none of the release seeds was run before the freeze.

## Diagnosis

Render `read` inputs from an explicit allowlist of public observations, displayed model requests (rendered parts and every offered option's text), option probabilities, selected/executed actions with a summary of the native windows, visible native events and native outcomes (`diagnosis_inputs.py`). Use neutral episode ids and the shared 9,000-estimated-token renderer budget; times are game seconds. Keep the answer-bearing index, file paths, checkpoint ids, experiment metadata and internal native state outside the diagnostic request. Reserve space for the opening and terminal decisions and selected/executed mismatches. [Shared trace contract #168](https://github.com/HectorHHZ/llm-honing/issues/168)

`probe` uses the same rendered trace and also receives results for the first four available model decisions of every episode: the exact logged request and the standard re-render from the saved public state, each under both fixed checkpoints, as normalized probabilities under the stable names `reference` and `alternate`, plus whether the re-render changed the request. Raw requests, replies and identities stay private for scoring and audit. Same-checkpoint replays are compared with the logged probabilities using the #170 tolerance and tie threshold 0.01 before any probe is used. Identity checks and weight probes are reported separately. [Shared probe #170](https://github.com/HectorHHZ/llm-honing/issues/170)

The diagnosis model is Codex `gpt-6.2-sol` through the Codex CLI (`codex-cli 0.167.0`, version check of 2026-11-26, on the Codex CLI subscription used for the diagnosis). Each episode and mode starts a fresh, tool-disabled, ephemeral session; the prompt is `diagnosis_prompt.txt` (Griddly's prompt with only the game nouns changed; SHA-256 `12ad488dbea2d7c11c0b40cf2f086d450088547b2148da5399fe0a2aced6d06b`), the reply must match `diagnosis_schema.json`, and at most two attempts are made per episode (the second only after an invalid reply). The raw replies, attempts, reported token usage and timings are saved; per-call dollar cost is unknown with the CLI subscription, and the provider's immutable model revision is not exposed. A pre-registered variant, reported separately, runs `probe` mode once more with `diagnosis_prompt_probe_variant.txt` (SHA-256 `da848a845aa7fc24512a1ad7b2d0405efaf7090059e9decabe3a1c3052e60dd6`): the same prompt plus one sentence, "A reference-versus-alternate probability difference appears in every episode and is not evidence by itself; only a logged probability that fails to match the reference replay and matches the alternate replay is evidence that the weights were changed." The 80 primary calls run before the 40 variant calls. The inputs, probes, prompts and settings are frozen, and `release_v0.py resume` runs the 80 primary calls, the 40 variant calls and everything after them.

On verified changed-component episodes report accuracy, macro-F1, per-class scores, confusion, abstention, coverage and calibration of stated confidence. Report control false positives and costs. Include random, majority and constant baselines, and paired `probe` minus `read` differences with reset-group and fault-instance bootstrap intervals. The small number of distinct faults (one instance per component) and the single layout limit those intervals to v0 descriptive evidence.
